Проект «Widget for Recent Successful Bank Operations»
Виджет для личного кабинета клиента банка, отображающий последние успешные банковские операции пользователя. Основная задача — подготовка и фильтрация данных на бэкенде для UI.

Установка проекта
Клонирование репозитория:

bash
git clone https://github.com/Spectral82/Spctrl82
Инициализация виртуального окружения:

bash
python -m venv venv
Убедитесь, что Python добавлен в переменную PATH.

Активация окружения:

Для macOS и Linux:

bash
source venv/bin/activate
Для Windows:

bash
venv\Scripts\activate
Или используйте poetry shell (если установлен плагин poetry-plugin-shell).

Установка зависимостей:

Через requirements.txt:

bash
pip install -r requirements.txt
Через Poetry (для линтеров):

bash
poetry add --group lint flake8
# или
poetry add mypy

## Функциональность

- Поиск операций по описанию (с поддержкой регулярных выражений, регистронезависимо).
- Агрегация и подсчёт операций по категориям.
- Маскирование номеров счетов и карт.
- Чтение данных из CSV и JSON.
- Интеграция с внешними API (курсы, справочники и т.п.).
- Логирование операций и ошибок (отдельные лог-файлы для модулей).
- Покрытие тестами (pytest) и отчёт о покрытии кода.

## Лог-файлы

- `masks.log` — логи модуля `masks.py` (уровень DEBUG и выше).
- `utils.log` — логи модуля `utils.py`.

Описание модулей и файлов
Папка src/
Это основная папка с исходным кодом. Все импорты идут относительно неё (например, from src.processing import ...).

src/__init__.py
Делает src пакетом Python. Часто пустой или содержит версии/экспорт публичных API. В Spctrl82 может использоваться для удобного импорта или регистрации подпакетов.

src/main.py
Точка входа в приложение. Содержит функцию main(), которая запускает демонстрацию/основную логику: поиск операций, подсчёт по категориям и т.п. Обычно вызывается как python -m src.main либо python src/main.py.

src/widget.py
Вспомогательные функции для работы с данными, часто связанные с форматированием/парсингом. В проекте есть get_date — скорее всего, преобразует строки в даты или нормализует формат дат для операций.

src/masks.py
Модуль для маскирования конфиденциальных данных: номера счетов, карт и т.д. Содержит функции вроде mask_account_number, mask_card_number. В нём также настраивается логгер (logger = logging.getLogger(__name__)), уровень DEBUG, FileHandler для masks.log, логирование успешных и ошибочных случаев.

src/processing.py
Основная логика обработки транзакций. Здесь находятся:

process_bank_search — поиск по описанию с использованием re (регулярные выражения), регистронезависимый, с экранированием спецсимволов.

process_bank_operations — подсчёт/агрегация операций по категориям.
Также могут быть вспомогательные функции фильтрации/сортировки, либо они вынесены в utils.py.

src/decorators.py
Декораторы для общего поведения: логирование вызовов, обработка исключений, повторные попытки, ограничение скорости и т.п. В тестах (test_decorators.py) проверяется поведение декоратора log и корректность строк в логах.

src/generators.py
Функции-генераторы или фабрики тестовых/демо-данных: списки транзакций, словари операций и т.д. Используются в демо и тестах для воспроизводимости.

src/utils.py
Утилиты общего назначения: валидация, вспомогательные вычисления, форматирование, работа с конфигурацией. В нём настраивается свой логгер по шаблону logger = logging.getLogger(__name__), чтобы не дублировать имя вручную. Здесь же могут быть функции, которые используют .env переменные.

src/external_api.py
Интеграция с внешними API: запросы к банковским/финансовым сервисам, получение курсов, справочников и т.п. Обработка ошибок сети, таймауты, преобразование ответов в внутренний формат.

src/data_reader.py
Чтение данных из файлов: transactions.csv, JSON и т.д. Нормализация полей, приведение типов, обработка ошибок чтения, пропуски/некорректные строки.

Папка tests/
Тестовый пакет проекта.

tests/__init__.py
Пустой или минимальный файл, чтобы папка была пакетом.

tests/conftest.py
Общие фикстуры pytest: sample_data, временные директории, моки внешних API, настройка окружения для тестов. Используется во всех тестах без явного импорта.

tests/test_main.py
Тесты точки входа main.py: запуск, вывод в консоль, корректность демо-сценариев, отсутствие исключений при стандартных данных.

tests/test_widget.py
Тестирование функций из widget.py (например, get_date): корректность парсинга дат, краевые случаи, ошибки формата.

tests/test_masks.py
Проверка маскирования: длина маски, сохранение формата, покрытие разных типов номеров. Также проверяется работа логгера и запись в masks.log.

tests/test_processing.py
Функциональные тесты processing.py: поиск по подстроке/regex, подсчёт операций, граничные условия (пустой список, спецсимволы, регистр).

tests/test_decorators.py
Поведение декораторов: логирование, обработка исключений, соответствие строк в логе ожидаемым значениям (в том числе исправление ошибок, когда строка в логе не совпадает с ожидаемой в тесте).

tests/test_generators.py
Корректность генерации данных: типы, обязательность полей, отсутствие дублей, соответствие схеме транзакций.

tests/test_utils.py
Юнит-тесты утилит: валидации, форматирования, вспомогательных функций. Здесь могут быть тесты на NameError и другие ошибки, если они возникали при рефакторинге.

tests/test_external_api.py
Моки внешних запросов, проверка обработки ошибок API, таймаутов, валидация структуры ответов.

tests/test_data_reader.py
Чтение CSV/JSON: обработка заголовков, кодировок, пропущенных значений, ошибок формата, проверка типов данных после чтения.

Файлы данных и конфигурации
data/operations.json
Пример данных в JSON-формате: список операций/транзакций. Используется для демо, тестов или локальной проверки.

data/transactions.csv
CSV-файл с транзакциями: дата, описание, сумма, категория, счёт/карта и т.д. Используется модулем data_reader.py.

.env
Переменные окружения для запуска: API-ключи, пути, флаги режимов, настройки логирования и т.п. Не должен попадать в Git.

.env.example
Шаблон .env: список переменных без реальных значений. Позволяет быстро собрать окружение.

Инструменты, отчёты, логи
htmlcov/
Папка с отчётом покрытия кода (coverage.py + pytest). Содержит HTML-отчёт: какие строки покрыты тестами, какие нет. Обновляется после запуска тестов с флагом покрытия.

masks.log
Лог-файл модуля masks.py: события маскирования, ошибки, предупреждения. Уровень DEBUG фиксирует детали.

utils.log
Лог-файл модуля utils.py: вспомогательные операции, ошибки валидации и т.п.

Инфраструктура и настройки
venv/
Виртуальное окружение Python (может быть названо иначе). Изолирует зависимости проекта.

poetry.lock и pyproject.toml
Управление зависимостями через Poetry. В pyproject.toml — метаданные проекта, зависимости, скрипты. poetry.lock фиксирует точные версии пакетов.

requirements.txt
Альтернативный список зависимостей (для pip). Может дублировать или дополнять Poetry.

Правила игнорирования для Git: venv/, __pycache__/, .env, логи, отчёты покрытия, IDE-файлы и т.п.

## Установка и запуск

### Через Poetry (рекомендуется)

```bash
poetry install
poetry run python -m src.main
Через venv и pip
bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
python src/main.py
Перед запуском скопируйте .env.example в .env и заполните переменные.

Линтинг и форматирование
bash
flake8 src tests
Для форматирования импортов:

bash
isort src tests
Особенности реализации
Для поиска по описанию используется библиотека re с экранированием спецсимволов и регистронезависимым поиском.

В модулях masks.py и utils.py настроены отдельные логгеры через logging.getLogger(__name__).

Конфиденциальные данные маскируются с сохранением формата (первые/последние символы видны).

Данные загружаются через data_reader.py, поддерживаются CSV и JSON.

Тестирование
Проект покрыт тестами с использованием библиотеки pytest.

Запуск тестов:

Чтобы запустить тесты, выполните команду:

bash
pytest tests/
Покрытие тестами
Код проекта покрыт тестами более чем на 80 %, что обеспечивает его надёжность и стабильность.

Отчёты по покрытию:

Чтобы сгенерировать HTML‑отчёт по покрытию тестами:

Выполните команду:

bash
pytest --cov=.
Откройте отчёт в папке htmlcov — файл index.html в браузере.

Отчёт покажет:

процент покрытия кода тестами;

какие строки кода не покрыты тестами;

детализацию по файлам и функциям.
